# React-прототип: распространение защиты и владение исходным текстом

Одноразовый проверочный артефакт для [тикета прототипа](https://github.com/PaterSantyago/puncta/issues/37). Не реализация `@use-puncta/with-react` и не приёмка библиотеки. На момент сохранения технические наблюдения получены; итоговое HITL-решение владельца ещё не принято.

## Открыть и воспроизвести

Откройте **[prototype.html](./prototype.html)** двойным щелчком. React и React DOM включены в файл; сеть и сервер не нужны. В GitHub файл нужно скачать через Raw / Download, затем открыть локально.

Для пересборки и повторения серверных наблюдений:

```sh
cd packages/with-react/prototype
npm ci --ignore-scripts --workspaces=false
npm run demo
npm run observe
```

Закреплены React / React DOM 19.3.0 и esbuild 0.28.2; полное дерево зависимостей — в `package-lock.json`. Серверный прогон выполнен на Node 24.21.0. Браузер: Chromium 151.0.0.0 на macOS, development React + StrictMode. Начальный прогон также работал на Node 20.18.0; это наблюдение, а не обещание поддержки Node проекта.

## Вопрос и механизм

Можно ли передать неотменяемую защиту из доступного поддерева через непрозрачный `Card` во вложенный `Puncta`, сохранив владение исходными children, типы элементов, key, ref и прочие props без дополнительных DOM-узлов?

В `mechanism.mjs`:

- `Puncta` читает настройки из React Context и преобразует только принадлежащие ему доступные текстовые листья.
- На `Puncta`, `PunctaProvider` и пользовательских компонентах обход останавливается. Возвращается исходный элемент с исходными children; компоненты пользователя не вызываются вручную.
- `PunctaProvider` передаёт настройки и сам не преобразует children.
- Под доступным `code` или `data-puncta="off"` Context получает `blocked: true`. Защищённые children не обходятся; вложенные компоненты получают запрет при обычном React-рендере. `enabled=true` не сбрасывает унаследованный запрет.
- Context-мост находится **внутри host-элемента** и присутствует также в незащищённом состоянии. Поэтому переключение `data-puncta` не заменяет host или позицию дочернего компонента. Сам host клонируется с заменой children; его тип, key, ref и остальные props сохраняются.
- Заглушка `mark` добавляет `⟦локаль:исходник⟧`. Она намеренно не идемпотентна: второй владелец добавил бы вторую пару маркеров. Новые props всегда обрабатываются от текущих исходных children.

В преобразовании нет DOM, эффектов, I/O или глобальных отметок обработки. DOM читается только панелью наблюдений после commit. `inspect` / `inspectRoot` — внутренний инструмент этого опыта, **не** проектируемый публичный `transformReact`: он добавляет служебные Provider. Публичная чистая функция по контракту не должна связывать возвращённое дерево с Context.

## Наблюдения

Серверный вывод сохранён в [observations.txt](./observations.txt), последний браузерный снимок данных — в [browser-observation.json](./browser-observation.json), экран — в [prototype-browser.png](./prototype-browser.png).

| Сценарий | Наблюдение |
| --- | --- |
| `Puncta > code > Card > Puncta enabled=true` | `Card source` остаётся исходным |
| Доступный `data-puncta="off" > Card > Puncta` | Тот же исходный текст; независимая соседняя область обрабатывается |
| `Card` без защиты | Ровно `⟦es-es:Card source⟧`; внешнего маркера нет |
| Доступный вложенный `Puncta` | Получает исходник, добавляет только свой маркер |
| Вложенный `Provider` | `Provider raw` остаётся исходным, свой `Puncta` обрабатывает собственный текст |
| Предок `enabled=false`, потомки включены | Исходник сохраняется через Provider и Card |
| Смена локали и исходника, повторный render | Ровно один актуальный маркер, без накопления преобразований |
| Клонирование доступного элемента | Тип / key / ref / style / handler / title сохранены по ссылке или значению |
| Браузерный DOM | Ожидаемые теги и вложенность, без добавленных DOM-обёрток |
| `a: 1` → перестановка `b, a` → защита → снятие защиты | Счётчик `a: 1` и тот же DOM-узел ref сохранены |
| Кнопка внешней области | Сохранённый обработчик вызван, счётчик вызовов увеличился |
| Чтение защищённого поддерева | Пустой список входных листьев, 0 чтений props дочернего Proxy, child сохранён по ссылке |
| Некорректная локаль / вложенный instance при отключении | Выполняемый компонент по-прежнему сообщает ошибку настройки |

В браузере после каждого шага оставались **12 / 12** успешных наблюдений. Последовательность: клик `a`, перестановка, `off`, снятие защиты, смена локали, повторный render, обратная перестановка, `code`, `off`, снятие защиты, все четыре шага вкладки «Исходники», клик по внешней кнопке. Ошибок и предупреждений React в консоли не было; присутствовало только информационное предложение установить React DevTools.

Это проверка конкретного механизма и сценариев. Счётчики вызовов render не используются как критерий: StrictMode имеет право повторять вычисления. Успешность определяется конечным текстом, исходными входами внешнего обхода, ссылочной идентичностью и состоянием после действий.

## Границы и вывод для обсуждения

В проверенных сценариях противоречие контракту не обнаружено. Context-мост и остановка обхода на границах областей дают работоспособный механизм. Рекомендация — признать узкую техническую предпосылку подтверждённой после обсуждения с владельцем, не переносить этот код в библиотеку как готовый адаптер.

Прототип намеренно знает только используемые host-типы, строки, массивы, Fragment и минимальные props `instance`, `locale`, `enabled`. В нём нет полных правил типографики, options/reset, всего каталога HTML-защиты, языковых границ, числовых листьев, произвольных iterables, Suspense, порталов, RSC, публичной диагностики или расчёта координат. Стабильность всех возможных React-структур не доказана этими примерами. Не измерялись стоимость Context-мостов и производительность больших деревьев.

`renderToStaticMarkup` здесь помогает наблюдать структуру и текст. Он не заменяет обязательные проверки `renderToString`, обоих streaming API, hydration, параллельных запросов и RSC. Полный языковой корпус, серверная матрица и npm-приёмка остаются задачами реализации по согласованной спецификации.
