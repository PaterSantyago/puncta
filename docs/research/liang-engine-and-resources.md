# Движок Liang и контролируемые ресурсы переносов en-gb и es-es

Исследование для [Движок Liang и контролируемые ресурсы переносов en-gb и es-es](https://github.com/PaterSantyago/puncta/issues/35), 15 сентября 2026 года. Основание — итоговый [контракт алгоритмических переносов](https://github.com/PaterSantyago/puncta/issues/29#issuecomment-5683906630) и [исследование несловарных переносов](https://github.com/PaterSantyago/puncta/blob/d6c8b1ce9cd09309fdc3d6d96225d45b75c0f125/docs/research/algorithmic-hyphenation.md).

**Статус:** техническая рекомендация, не принятое решение о зависимости и не языковая приёмка. Продукт не реализовывался. Исходники исследованы на перечисленных ниже commit; проверки выполнены отдельно от пакетов Puncta, в Node 20.18.0 и Python 3. Проверки браузеров, SSR/streaming/hydration и поддерживаемой матрицы Node не проводились.

## Вывод и рекомендация

Для следующего этапа рекомендован **не публичный строковый API `hyphen`, а небольшой контролируемый ESM-порт его `hyphenateWord` и `levelsToMarkers`**, с подготовленными при сборке таблицами из `hyph-utf8`: en-gb в commit `5684c0f…`, es 5.0 в том же commit. Он уже возвращает позиции, не загружает файлы, не использует DOM и при непосредственном вызове не имеет кеша слов или настроек между вызовами. Это позволяет оставить сегментацию, допуск слов, минимумы, исходные координаты и SHY адаптеру Puncta. Объём выбранных исходников — `hyphenate-word.js` 2 281 байт и `markers.js` 956 байт; из второго нужна только `levelsToMarkers`, а из первого следует убрать блок `DEV`. Это размеры исходных файлов, не измерение будущего бандла. [Ядро][word], [преобразование весов][markers], [сборка upstream][build-src]

Предлагаемый ресурс en-gb исключает восемь записей `hyphenation`; дополнительно можно убрать четыре полностью привязанных шаблона для четырёхбуквенных слов. Эта дополнительная фильтрация не меняет результат при принятом минимуме en-gb 2/3. Для es отсутствуют и отдельные целословные исключения, и полностью привязанные шаблоны; используются все 4 694 шаблона проверенного файла. Ни таблицы готовых исключений пакета `hyphen`, ни готовый en-gb WASM Hyphenopoly использовать нельзя. Детали и границы доказательства ниже.

Это конкретный кандидат для реализации после завершения wayfinder. **Решения владельца ещё нужны** в задаче [Публичный API core, локалей и React](https://github.com/PaterSantyago/puncta/issues/31) о публичной форме готовности/ошибок и в задаче [Критерии приёмки первой версии](https://github.com/PaterSantyago/puncta/issues/33) о независимых языковых эталонах, покрытии и выявляемой неоднозначности. В решении о публичном API владелец должен также принять или отклонить поддержку контролируемой производной внутреннего кода `hyphen`: это собственная ответственность за обновления, а не установка готового стабильного API. Библиотека и ресурсы не становятся утверждёнными только из-за этой рекомендации. Принятый контракт переносов не пересматривается.

## 2. Происхождение и исключения: что установлено

### en-gb

В заголовке `hyph-en-gb.tex` указано получение шаблонов PATGEN из 114 925 размеченных британских слов OUP. По контракту обучение по словарю разрешено. Ресурс содержит 8 527 шаблонов и отдельный блок из восьми исключений: `university`, `universities`, `however`, `manuscript`, `manuscripts`, `reciprocity`, `throughout`, `something`. Их готовые позиции запрещены контрактом независимо от формы упаковки. Историческая оценка автора на обучающем списке не является оценкой Puncta. [Исходный файл][tex-en]

Внутри `patterns` найдены ровно четыре шаблона с обоими якорями: `.an4on.`, `.di4al.`, `.du4al.`, `.ed4it.`. Это **не доказательство**, что они внесены как запрещённые ручные исключения: они находятся в блоке, заявленном как результат PATGEN. Якоря ограничивают область совпадения; сами по себе они не устанавливают происхождение. Предлагаемое удаление всех четырёх — сознательная дополнительная фильтрация ради простой проверяемой структуры ресурса, а не новое толкование запрета. Все четыре совпадают только с четырёхбуквенными словами; допустимой позиции en-gb с двумя буквами слева и тремя справа у них быть не может. Поэтому удаление не влияет на согласованный результат даже независимо от ограничения длины 6. [Шаблоны][tex-en], локальная инвентаризация в приложении.

В upstream `hyphen` сборщик помещает исключения в третий элемент таблицы, а фабрика использует его даже при `exceptions: []`. В Hyphenopoly `tex2json.js` превращает восемь исключений в полностью привязанные шаблоны с весами 8/9; en-gb JSON содержит 8 535 записей — исходные 8 527 плюс эти восемь. Очистка runtime-параметра не может изменить уже скомпилированный WASM. [Сборщик hyphen][build-patterns], [фабрика][factory], [конвертер Hyphenopoly][hp-converter], [готовый JSON][hp-en]

### es 5.0

В фиксированном `hyph-es.tex`: 4 694 шаблона, нет блока `hyphenation`, нет шаблонов с обоими якорями. Генератор сначала создаёт общие сочетания согласных; затем читает только `eshyph.src`. В `.src` обычные шаблоны переписываются, `/prefix/` разворачивается в шаблоны перед гласными/`h`, `*stem` — в шаблон с `des`. Это правила фрагментов и семейств, включая ручные морфологические уточнения, а не поиск полного слова с готовыми позициями. Границу «языковые данные допустимы» нельзя незаметно заменить на «разрешены только короткие универсальные сочетания». [Генератор][es-generator], [данные префиксов и особых случаев][es-cases]

README описывает проверку правил по словарным данным и их смешанное происхождение; словарь не входит в предлагаемый ресурс. Отдельный `eshyphexh.tex` относится к традиционным правилам для `h` и содержит явные исключения — он исключается из входов полностью. При подготовке от фиксированного TeX-файла генератор испанского языка заново не запускается и дополнительные файлы не подмешиваются. [README][es-readme], [традиционные исключения][es-exceptions]

**Граница доказательства:** исследована явная цепочка источников, содержимое выбранного снимка и механика двух конвертеров. Не восстановлена вся историческая подготовка OUP/PATGEN и не доказана языковая корректность каждого ручного испанского шаблона. Проверка отсутствия двойных якорей — полезный инвариант предлагаемой производной, но не универсальный детектор любых исторически скомпилированных исключений. При смене ресурса одного регулярного выражения недостаточно: нужен повторный аудит происхождения и преобразований.

## 3. Воспроизводимая подготовка ресурса

### Рецепт

1. Получить два TeX-файла по фиксированному commit и проверить SHA-256 из таблицы. Не брать уже сгенерированные языковые JS/WASM и не исполнять TeX через `eval`.
2. Для этих конкретных файлов удалить комментарии `%…` до конца строки, извлечь ровно один блок `\patterns{…}` и разделить его по пробельным символам. Внутри блока разрешить только латинские буквы соответствующего источника, цифры весов и `.` на краях; при неожиданной команде/скобке/внутренней точке остановить сборку. Это ограниченный парсер двух проверенных файлов, не общий TeX-парсер.
3. Полностью исключить `hyphenation`, `*.hyp.txt`, `eshyphexh.tex`, готовые таблицы исключений и любые этапы их компиляции. У en-gb удалить **ровно перечисленные четыре** полностью привязанных шаблона; при изменении перечня остановить сборку для аудита. es не изменяется.
4. Сохранить исходный порядок шаблонов. Канонический промежуточный формат: UTF-8, одна запись на строку, LF, включая последний LF. Зафиксировать количество записей и SHA-256.
5. Преобразовать эти записи фиксированным `createPatternTrie.cjs`. Цифры задают вес границы; буквы образуют путь в trie, `.` остаётся якорем. Компилятор принимает только массив шаблонов и возвращает `[weights, trie]`; третий элемент исключений отсутствует. Преобразовать строки весов в массивы чисел, записать результат как ESM-данные. Сам CJS-компилятор нужен только при подготовке. [Исходник компилятора][compiler]
6. Проверить набор всех путей полученного trie против буквенных частей входных записей, числовые веса и количество терминальных записей. В проверенных производных нет повторяющихся путей после удаления цифр. На новых данных при дубле сборку следует останавливать: текущий upstream-компилятор перезаписывает весовой вектор последней записью, а не объединяет дубли через `max`. Не исправлять это незаметно при обновлении. Во время вычисления совпадающие шаблоны объединяются покоординатным максимумом — это отдельная операция Liang. [Компилятор][compiler], [вычислительное ядро][word]
7. Приложить к версии пакета локали manifest происхождения: URL+commit исходника, SHA-256 входа/производной, версия преобразования/схемы, явные исключённые входы, алфавит допуска, минимумы, notices. Входы не скачиваются при преобразовании пользовательского текста. Повторная сборка из тех же входов должна дать те же байты; опубликованный пакет проверяется отдельно.

Шаги 1–5 опробованы локально до JSON-таблиц; создание публикуемых ESM-пакетов, полная проверка упакованного ресурса и автоматизация шагов 6–7 остаются работой реализации. Компилятор сохраняет `.`, а ядро добавляет `.` перед/после вычисляемого слова: собственная замена якоря на `_` ему не нужна.

Источники: [фабрика hyphen][factory], [обход][start], [упаковка][build-package], [ядро][word], [модуль Hyphenopoly][hp-module], [manifest][hp-package]. Мемоизация результатов алгоритма сама по себе не равна встроенному словарю исключений; отказ от неё здесь — способ упростить аудит и изоляцию, а не расширение запрета согласованного контракта.

**Предлагаемая архитектура поставки:** общий вычислительный код в core, неизменяемые таблицы внутри независимо устанавливаемых пакетов локалей. При статическом ESM-import ресурс готов синхронно после загрузки модуля; вычисление не требует сети/файлов/WASM и не должно инициировать загрузку. Опциональный динамический import пользователь или интеграция завершает до преобразования. Публичную форму API этого состояния определяет решение о публичном API. Отсутствующий/несовместимый ресурс при включённых переносах — согласованная ошибка настройки без частичного результата; при выключенных переносах новый ресурс для вставки SHY не требуется.

Рабочие массивы создаются на слово; таблицы можно разделять между запросами как неизменяемые. Минимумы, настройки и отображение исходных координат принадлежат конкретному вызову/экземпляру. Если позже вводить кеш, нельзя использовать общий изменяемый кеш выводимых строк без ключа версии ресурса и всех влияющих параметров; предпочтительнее сначала обойтись без него. Deep-freeze таблиц в локальной пробе не вызвал ошибки записи и результат совпал с эталонным вычислением; это ограниченная проверка чистоты ядра, не проверка SSR-системы.

Для серверно-клиентского совпадения требуются одинаковые версии ядра/таблиц/правил допуска, одинаковая нормализация и сегментация, настройки и контекст области. Один `Intl.Segmenter` без согласования поведения разных runtime не доказывает воспроизводимость. При streaming область может быть незавершённой; момент её обработки и размещение SHY в текстовых узлах принадлежат решениям [Области текста](https://github.com/PaterSantyago/puncta/issues/30) и о публичном API. Готовность ресурсов должна проверяться до выдачи результата; скрытой замены CSS-переносами нет. Эти интеграционные требования следуют из контракта переносов, а не из результатов локальной пробы.

Основания: [код ядра][word], [контракт алгоритмических переносов](https://github.com/PaterSantyago/puncta/issues/29), [контракт диагностики](https://github.com/PaterSantyago/puncta/issues/32). Расширенные графемные кластеры определяет [UAX #29, revision 47][uax29]; NFC — [UAX #15, revision 57][uax15]. Это спецификации, не доказательство одинаковой реализации сегментации в каждом runtime.

Практичный первоначальный допуск для выбранных данных: en-gb `a–z`, es-es `a–z á é í ó ú ü ñ`, с соответствующими прописными только в разрешённой форме. Это **рекомендация**, которую надо закрепить и проверить в приёмке. В самих испанских шаблонах нет `ü`, но она используется как буква между совпадающими согласными шаблонами; нельзя автоматически вывести полный допустимый алфавит как множество символов из trie. Локальная проба с `pingüino` и `vergüenza` демонстрирует вычисление, не нормативную сертификацию. Английские заимствования с диакритикой первоначальный ASCII-допуск пропустит с предупреждением.

Для NFD `cancio\u0301n` внутренний NFC-вид `canción` содержит одну букву `ó`; положение после неё отображается за исходные `o`+U+0301. Если графема не сводится к одной поддерживаемой букве (неожиданная комбинация, ZWJ, variation selector, суррогат вне алфавита), следует сохранить слово с причиной «неподдерживаемые символы». Это предотвращает передачу неподдерживаемых последовательностей UTF-16 ядру. Политика графем и обратная карта пока не реализованы и не испытаны этим исследованием.

## 6. Испанский Испании и качество производной

`es` 5.0 — общий испанский ресурс, не отдельный сертифицированный `es-es`. Генератор содержит `2t2l`, а README описывает морфологические уточнения и работу с заимствованиями. Региональная метка сама по себе не выбирает произношение `tl`: RAE допускает различия внутри Испании. Морфологические переносы требуют существования компонентов и продуктивного префикса; для `h` существенны слоговая структура и произношение. Простое распознавание букв этих свойств не доказывает. [Испанские данные][es-cases], [README][es-readme], [RAE, guion §§2.5–2.8][rae]

Поэтому нельзя обещать, что все результаты общего `es` без адаптации соответствуют принятой осторожной политике Puncta. Например, обнаруженный класс `tl` можно целиком пропускать при отсутствии информации о произношении. Это консервативное предложение для решения о критериях приёмки первой версии, а не утверждённое правило локали; автоматически объявлять все остальные слова однозначными нельзя. Требуется перечислить, какие неоднозначности система действительно умеет обнаруживать, и закрепить причины предупреждений. Находить «неизвестные слова» без лексикона эта схема не умеет.

После исключения восьми готовых en-gb записей покрытие уменьшается. Проверка выбранного ядра с исходными шаблонами, но без таблицы исключений дала:

| Слово                       | Позиции шаблонов | Позиции отдельного upstream-исключения |
| --------------------------- | ---------------- | -------------------------------------- |
| `university`                | `[3]`            | `[3,6]`                                |
| `universities`              | `[3,9]`          | `[3,6,9]`                              |
| `however`                   | `[]`             | `[3]`                                  |
| `manuscript`, `manuscripts` | `[]`             | `[2,4]`                                |
| `reciprocity`               | `[2,7]`          | `[2,4,7]`                              |
| `throughout`                | `[]`             | `[7]`                                  |
| `something`                 | `[]`             | `[4]`                                  |

Индексы — после указанного числа букв; en-gb минимум 2/3 выполнен. Столбец исключений приведён для аудита потери покрытия и **не предлагается к поставке/восстановлению**. Сходство с upstream-исключением не является независимой приёмкой.

Удаление четырёх полностью привязанных шаблонов само по себе разрешает сырые позиции `[2]` в `anon/dial/dual/edit`, где раньше было `[]`; фильтр en-gb 2/3 их запрещает. Это наглядная причина не считать удаление запрещающих шаблонов автоматически безопасным для качества. В предлагаемом es удалений нет, значит новая потеря именно от удаления исключений не наблюдается; качество исходного es и последствия будущих ограничений допуска всё равно подлежат проверке.

### Проверяемые требования к корпусу для решения о критериях приёмки первой версии

1. Для **каждой** локали отдельный независимый набор, проверенный компетентным редактором с источником каждой языковой оценки. Отделить разрешённые позиции, обязательные положительные примеры и намеренные пропуски. Считать ошибочно добавленные позиции и пропуски раздельно; ноль ошибочных позиций на принятом корпусе — требование согласованного контракта переносов, а не вывод исследования. Размер и минимальное покрытие устанавливает владелец в решении о критериях приёмки первой версии.
2. Для en-gb включить британское написание, производные/суффиксы, разную длину слов и слова, потерявшие исключения. Последние нужны для отслеживания пропусков; нельзя использовать таблицу upstream как независимый нормативный источник.
3. Для es-es покрыть соседние гласные/диакритику, `h`, `ch/ll/rr`, `x`, `tl`, префиксы и ложные префиксы, заимствования. Редактор отдельно отмечает случаи, в которых позиции зависят от анализа или произношения. Принятые правила обнаружения неоднозначности проверяются на целых словах, а не на отдельных неверных позициях.
4. Отдельная техническая матрица: NFC/NFD с точным сохранением исходных букв; регистр; все согласованные апострофы/дефисы; цифры; смешанные письменности; неподдерживаемые графемы; авторские SHY; длина и повышенные минимумы; защита; повторная обработка; чистый экспорт. Нет предупреждений на ожидаемых пропусках; предупреждения на согласованных обнаруженных проблемах; каждая вставка имеет правильную исходную координату.
5. Сервер/клиент и streaming/hydration: одинаковые версии ресурсов и сегментации, параллельные области/экземпляры с разными настройками, отсутствующие/несовместимые ресурсы, отсутствие частичного результата и сетевого I/O при преобразовании. Повторить на поддерживаемых runtime и после упаковки локалей.
6. Для поставляемых данных: воспроизводимые контрольные суммы, только разрешённые входы, отсутствие таблиц/компиляции целословных исключений, полный аудит нового upstream-снимка, notices внутри опубликованного tarball. Совпадение с другой библиотекой либо с обучающим списком не засчитывать как языковую приёмку.

## 7. Выполненные проверки и воспроизведение

В изолированной пробе входные таблицы после компиляции рекурсивно заморожены. `hyphenateWord` вызван напрямую; отладочный `console.log` из блока `DEV` временно подавлен только в процессе пробы. Выход сравнивался с отдельно записанным стандартным сопоставлением шаблонов Liang: проход по всем началам в `'.'+word+'.'`, покоординатный максимум весов, нечётные веса → позиции, минимум 2/2 как у сырого ядра.

- **15 входов en-gb:** восемь слов исключений, `example`, `representation`, `internationalisation`, четыре слова полностью привязанных шаблонов. Расхождений вычислительных реализаций — 0.
- **55 159 входов es:** записи фиксированного `tools/spanish-words.txt`, удовлетворяющие `/^[a-záéíóúüñ]+$/` и длине от 6. Расхождений — 0. Этот список upstream не независим, не содержит проверенной нами разметки и использован только для технического сравнения. [Входной список][es-words]
- Проверены числа записей, SHA-256 исходных и промежуточных файлов, отсутствие повторяющихся путей, восемь добавленных исключений в JSON Hyphenopoly, сырые позиции при удалении четырёх шаблонов.

**Не выполнено:** независимая языковая оценка, браузерные испытания, SSR/React/HTML, сегментация/обратная карта, пакетная поставка, бенчмарки, поддерживаемая runtime-матрица. Ни одно из перечисленных чисел не является процентом точности языка.

### Минимальный воспроизводимый аудит данных и ядра

Сначала checkout четырёх репозиториев по commit из §1 в каталогах `hyphen`, `tex-hyphen`, `tex-hyphen-spanish`, `Hyphenopoly`; не использовать их плавающий HEAD. Следующий Python запускается из общего каталога и создаёт только исследовательский `audit-data.json`:

```python
import hashlib, json, pathlib, re

base = pathlib.Path("tex-hyphen/hyph-utf8/tex/generic/hyph-utf8/patterns/tex")
expected = {
    "en-gb": "e95bb4ab350f620c41c231c4785d7bdb4f91949d3e631b30e08b3ead3c340a52",
    "es": "6a2e5f39a991a23d1cd8a23dbd0f6fe96a9f07561a6695f4f3320f47030e236c",
}
result = {}
for lang, digest in expected.items():
    raw = (base / f"hyph-{lang}.tex").read_bytes()
    assert hashlib.sha256(raw).hexdigest() == digest
    text = re.sub(r"%[^\n]*", "", raw.decode("utf-8"))
    blocks = re.findall(r"\\patterns\{([^}]*)\}", text)
    assert len(blocks) == 1
    patterns = blocks[0].split()
    assert all(re.fullmatch(r"\.?[a-záéíñóú1-9]+\.?", p) for p in patterns)
    anchored = [p for p in patterns if p.startswith(".") and p.endswith(".")]
    assert anchored == ([".an4on.", ".di4al.", ".du4al.", ".ed4it."] if lang == "en-gb" else [])
    clean = [p for p in patterns if p not in anchored]
    paths = [re.sub(r"[1-9]", "", p) for p in clean]
    assert len(paths) == len(set(paths))
    canonical = ("\n".join(clean) + "\n").encode("utf-8")
    print(lang, len(clean), len(canonical), hashlib.sha256(canonical).hexdigest())
    result[lang] = clean
pathlib.Path("audit-data.json").write_text(json.dumps(result, ensure_ascii=False))
```

Техническое сравнение, файл `audit.mjs` в том же каталоге; запуск `node audit.mjs`:

```javascript
import fs from "node:fs";
import crypto from "node:crypto";
import { createRequire } from "node:module";
import { hyphenateWord } from "./hyphen/src/hyphenate-word.js";
const require = createRequire(import.meta.url);
const { createPatternTrie } = require("./hyphen/scripts/createPatternTrie.cjs");
const data = JSON.parse(fs.readFileSync("audit-data.json", "utf8"));
const log = console.log;
console.log = () => {}; // suppress upstream DEV trace in this probe only
function freeze(x) {
  if (x && typeof x === "object") {
    Object.freeze(x);
    Object.values(x).forEach(freeze);
  }
  return x;
}
function reference(patterns) {
  const root = Object.create(null);
  for (const pattern of patterns) {
    let chars = "",
      values = [0];
    for (const c of pattern) {
      if (/[0-9]/.test(c)) values[values.length - 1] = Number(c);
      else {
        chars += c;
        values.push(0);
      }
    }
    let node = root;
    for (const c of chars) node = node[c] ??= Object.create(null);
    node.values = values;
  }
  return (word) => {
    const text = "." + word + ".",
      weights = Array(text.length + 1).fill(0);
    for (let i = 0; i < text.length; i++) {
      let node = root;
      for (let j = i; j < text.length && (node = node[text[j]]); j++) {
        node.values?.forEach(
          (v, k) => (weights[i + k] = Math.max(weights[i + k], v)),
        );
      }
    }
    return Array.from({ length: word.length + 1 }, (_, k) => k).filter(
      (k) => k >= 2 && k <= word.length - 2 && weights[k + 1] % 2 === 1,
    );
  };
}
const en = [
  "university",
  "universities",
  "however",
  "manuscript",
  "manuscripts",
  "reciprocity",
  "throughout",
  "something",
  "example",
  "representation",
  "internationalisation",
  "anon",
  "dial",
  "dual",
  "edit",
];
const es = fs
  .readFileSync("tex-hyphen-spanish/tools/spanish-words.txt", "utf8")
  .split(/\s+/)
  .filter((w) => /^[a-záéíóúüñ]+$/.test(w) && w.length >= 6);
for (const [lang, patterns] of Object.entries(data)) {
  const [weights, trie] = createPatternTrie(patterns);
  const table = freeze([weights.map((w) => [...w].map(Number)), trie]);
  const bytes = JSON.stringify(table),
    compare = reference(patterns);
  const words = lang === "en-gb" ? en : es;
  let mismatches = 0;
  for (const word of words) {
    if (
      JSON.stringify(hyphenateWord(word, word, ...table)) !==
      JSON.stringify(compare(word))
    ) {
      mismatches++;
    }
  }
  log(
    lang,
    words.length,
    mismatches,
    Buffer.byteLength(bytes),
    crypto.createHash("sha256").update(bytes).digest("hex"),
  );
  if (mismatches) throw new Error("Liang computation mismatch");
}
```

Код в приложении — воспроизводимая исследовательская проба, не реализация API Puncta. Ожидаемый вывод: en-gb `15 0 95569` и es `55159 0 51464`, затем SHA-256 таблиц из §3. Контроль отсечённых TeX-исключений проводится отдельно по исходному блоку; проба намеренно никогда не импортирует готовые словари исключений.
